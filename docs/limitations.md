# محدودیت‌ها — Limitations

> مرحله ۱ — ۲۰۲۶‑۱۰‑۱۴
> طبق قانون ۷ `Rules`: هیچ منبعی صرفاً به علت دشواری پیاده‌سازی حذف نشده است. این سند **دلیل** هر محدودیت و **جایگزین مجاز** آن را ثبت می‌کند تا هیچ محدودیتی پنهان نماند و هیچ قابلیت غیرممکن به‌عنوان ممکن معرفی نشود.

دسته‌بندی:
- **L1 — غیرممکن فنی روی اندروید** (سیستم اجازه نمی‌دهد)
- **L2 — ممنوع به دلیل سیاست سرویس/فروشگاه** (اجازه قانونی/سیاستی نداریم)
- **L3 — ممکن ولی مشروط به اقدام/هزینه کاربر**
- **L4 — محدودیت ذاتی داده** (حتی با دسترسی کامل هم قابل دستیابی نیست)
- **L5 — محدودیت اجرایی/مهندسی**
- **L6 — آگاهانه رد شده** (تصمیم ما، با دلیل)

---

## L1 — غیرممکن فنی روی اندروید

| # | مورد | چرا | جایگزین مجاز |
| --- | --- | --- | --- |
| L1‑1 | خواندن تاریخچه/کوکی/رمز مرورگرهای نصب‌شده | داده در پوشه خصوصی اپ دیگر است؛ scoped storage و sandbox اجازه نمی‌دهد | Takeout برای Chrome sync (H1)، CSV رسمی Google Password Manager (H2)، صادرات دسکتاپ Firefox/Safari/Edge (H3–H5) |
| L1‑2 | خواندن داده اپ‌های دیگر (دیتابیس، فایل، SharedPreferences) | سندباکس اندروید؛ بدون root ممکن نیست | واردکردن فایل‌هایی که خود اپ صادر می‌کند |
| L1‑3 | دسترسی به بکاپ سیستم (Google One / device backup) | API عمومی ندارد | Takeout و آرشیوهای رسمی |
| L1‑4 | تاریخچه دسترسی اپ‌ها به مجوزها (Privacy Dashboard / App Ops) | فقط سیستم | `UsageStatsManager` به‌عنوان تقریب استفاده (I2) + `checkPermission` برای وضعیت فعلی (I10) |
| L1‑5 | شمارش passkeyها/WebAuthn | Credential Manager فقط ساخت/استفاده را می‌دهد، شمارش نه | صادرات مدیریت‌کننده رمز و 2FA (L5, L6 در کاتالوگ) |
| L1‑6 | فهرست کامل حساب‌های دستگاه با `AccountManager` | از API 26 بدون انتخاب کاربر یا امضای مشترک با authenticator ممکن نیست | Credential Manager/account picker (B1)، همگام‌سازی مخاطبان (I3) |
| L1‑7 | Digital Wellbeing / زمان استفاده سطح سیستم | API عمومی ندارد | UsageStats با مجوز کاربر |
| L1‑8 | خواندن پیام‌های رمزنگاری‌شده سرتاسری (Signal و مشابه) | رمزنگاری E2EE | شواهد غیرمستقیم (ایمیل/پیامک واردشده) |
| L1‑9 | دسترسی به داده اپ‌های iOS/دسکتاپ روی همین دستگاه | خارج از دامنه اندروید | import آرشیو رسمی آن پلتفرم‌ها (Apple privacy export و…) |

## L2 — ممنوع به دلیل سیاست سرویس یا فروشگاه

| # | مورد | سیاست | جایگزین مجاز |
| --- | --- | --- | --- |
| L2‑1 | `READ_SMS` | Google Play: فقط اپی که **default SMS handler** است + Declaration Form؛ داده فقط برای عملکرد اصلی و ممنوع برای هر هدف دیگر | واردکردن فایل XML پیامک‌ها توسط کاربر (I5b) |
| L2‑2 | `READ_CALL_LOG` | فقط default Phone/Assistant handler | واردکردن CSV توسط کاربر (I6b) |
| L2‑3 | `QUERY_ALL_PACKAGES` | Play: فقط وقتی عملکرد اصلی اپ نیاز به دیدن همه اپ‌ها دارد + فرم + ویدیو؛ فهرست اپ‌ها داده شخصی حساس است و فروش/تبلیغ با آن ممنوع | تلاش برای فرم (چون کشف اپ‌ها یکی از عملکردهای اصلی است) + fallback `<queries>` هدفمند (I1b) با اعلام صادقانه پوشش کمتر |
| L2‑4 | `MANAGE_EXTERNAL_STORAGE` | Play محدود کرده | فقط SAF (I8) |
| L2‑5 | `AD_ID` | اگر برای تبلیغات استفاده نشود نباید درخواست شود؛ ارزش محصول هم ندارد | استفاده نمی‌شود |
| L2‑6 | Facebook/Instagram API برای داده شخصی | Graph API از ۲۰۲۰ برای داده شخصی کاربران عادی بسته شده | آرشیو «Download your information» (D1) |
| L2‑7 | تاریخچه خرید Amazon/eBay از طریق API | API مصرف‌کننده وجود ندارد؛ Amazon صفحه «Download order reports» را در ۲۰۲۳ حذف کرد | «Request your data» (E1) و ایمیل رسیدها (E6) |
| L2‑8 | Microsoft sign‑in logs برای حساب شخصی | نیاز به tenant سازمانی + لایسنس **Entra ID P1/P2** + نقش Reports Reader + `AuditLog.Read.All` | privacy dashboard archive (C3) + ایمیل‌های هشدار ورود |
| L2‑9 | Xbox / PSN / Nintendo API شخصی | API عمومی برای داده شخصی ندارند | آرشیو رسمی + ایمیل (C4, F3, F4) |
| L2‑10 | اسکوپ `gmail.readonly` بدون تأیید | اسکوپ **Restricted** است: نیازمند OAuth verification و در صورت ارسال داده به سرور ارزیابی امنیتی سالانه (CASA)؛ اپ تأییدنشده ≤ ۱۰۰ کاربر تست | چون backend نداریم و داده از دستگاه خارج نمی‌شود، مستندسازی «local‑only» برای verification؛ در صورت شکست: IMAP با توکن OAuth (A2) یا import Takeout (A6/B5) |
| L2‑11 | Reddit OAuth client جدید | از اواخر ۲۰۲۵ ثبت خودکار بسته شده و نیازمند تأیید دستی است؛ tier رایگان ۱۰۰ QPM و تجاری ~$0.24/۱۰۰۰ فراخوانی | «request your data» ردیت + import |
| L2‑12 | X API رایگان | از ۲۰۲۶ pay‑per‑use (~$0.01/user lookup، ~$0.005/post read) و بدون tier رایگان برای ثبت‌نام جدید | آرشیو رسمی X (account.js/tweets.js) |
| L2‑13 | bank/PSD2 در EU | دسترسی AIS فقط برای TPP دارای مجوز تنظیم‌کننده | واردکردن صورت‌حساب CSV/MT940 (E10) |
| L2‑14 | scraping سایت‌ها و موتورهای جست‌وجو | خلاف ToS و robots.txt | کاربر URL را خودش وارد می‌کند (J5) یا صفحه را دستی در مرورگر باز می‌کند و نتیجه را ثبت می‌کند |
| L2‑15 | self‑bot در Discord / کاربر-ربات در هر سرویس | خلاف ToS | OAuth رسمی برای endpointهای مجاز (`/users/@me*`) + بسته داده رسمی |

## L4 — محدودیت ذاتی داده (حتی با دسترسی کامل)

| # | مورد | توضیح |
| --- | --- | --- |
| L4‑1 | **تاریخ واقعی ثبت‌نام برای اکثر سرویس‌ها وجود ندارد** | فقط ~۱۱ منبع فیلد رسمی دارند (GitHub, GitLab, Stack Exchange, Steam, Roblox, Last.fm, Fitbit, YouTube channel, RDAP, Codeforces, قبض اپراتور). بقیه فقط شاهد غیرمستقیم می‌دهند و باید با `DateKind.ESTIMATED` + `derivation` ثبت شوند |
| L4‑2 | ایمیل‌های حذف‌شده بازگشت‌ناپذیرند | اگر کاربر ایمیل ثبت‌نام را پاک کرده، شاهد از بین رفته است؛ Takeout فقط پیام‌های موجود (شامل Spam/Trash) را می‌دهد |
| L4‑3 | حساب‌های حذف‌شده معمولاً هیچ API‌ای ندارند | فقط شواهد باقی‌مانده (ایمیل قدیمی، نقض داده، snapshot قبلی connector) → حداکثر `PROBABLE` |
| L4‑4 | Wayback پوشش ناقص دارد | نبود تصویر ≠ نبود حساب |
| L4‑5 | نقض داده تاریخ **نقض** را می‌دهد نه تاریخ ثبت‌نام | فقط کران بالا (`ACCOUNT_CREATED ≤ breachDate`) |
| L4‑6 | Chrome sync خاموش = هیچ تاریخچه‌ای در Takeout نیست | Takeout از حساب می‌خواند نه دستگاه |
| L4‑7 | Spotify recently played فقط ~۲۰ مورد آخر | تاریخچه کامل در API نیست |
| L4‑8 | YouTube watch history از API در دسترس نیست | فقط Takeout |
| L4‑9 | Gmail quota/سقف همزمانی | ۶٬۰۰۰ واحد/دقیقه/کاربر و سقف همزمانی منتشرنشده → اسکن کامل صندوق بزرگ زمان‌بر است |
| L4‑10 | YouTube Data API سهمیه روزانه ۱۰٬۰۰۰ واحد | افزایش نیازمند فرم audit |
| L4‑11 | داده‌های قبل از نصب اپ | app‑local sources (نصب اپ، usage) فقط از لحظه نصب به بعد دقیق‌اند؛ گذشته فقط از آرشیوها بازسازی می‌شود |
| L4‑12 | تفکیک «چند کاربر یک دستگاه» ممکن نیست | همه داده به owner نسبت داده می‌شود؛ اگر دستگاه مشترک است، کاربر باید آگاهانه انتخاب کند |
| L4‑13 | نام کاربری یکسان در سرویس‌های مختلف لزوماً یک نفر نیست | وزن پایین در همبستگی (۰٫۴) و هرگز به‌تنهایی `CONFIRMED` نمی‌دهد |
| L4‑14 | ایمیل‌های کاری/سازمانی ممکن است توسط ادمین محدود باشند | `AccessState.Blocked(POLICY)` با دلیل |
| L4‑15 | دسترسی شبکه‌ای منطقه‌ای | برخی سرویس‌ها در بعضی شبکه‌ها/مناطق در دسترس نیستند؛ اپ **هیچ ابزار دورزدن تحریم/فیلتر** پیاده نمی‌کند (قانون ۵ و ۱۱) و فقط وضعیت `REGION_BLOCKED` را صادقانه گزارش می‌دهد |

| # | مورد | اثر | کاهش |

| L5‑5 | `androidx.security:security-crypto` deprecated | نمی‌توان از EncryptedSharedPreferences استفاده کرد | Tink + DataStore + Keystore (ADR‑003) |

| L5‑9 | قالب آرشیوهای رسمی بدون قرارداد نسخه‌دار منتشر می‌شوند | شکست پارسر با تغییر سرویس | پارسر نسخه‌دار + golden fixtures + شکست صادقانه (`SCHEMA_MISMATCH`) |
| L5‑10 | OAuth verification گوگل می‌تواند هفته‌ها طول بکشد | تأخیر در انتشار عمومی مسیر Gmail API | مسیر IMAP/Takeout به‌عنوان جایگزین کامل |
| L5‑11 | Basic Auth مایکروسافت در حال حذف کامل برای IMAP/POP/SMTP (اعلام دسامبر ۲۰۲۶) | App Password برای Exchange Online متوقف می‌شود | XOAUTH2 اجباری در connector ایمیل مایکروسافت |

| L6‑5 | ذخیره رمز عبور / مقدار کوکی / secret 2FA | ریسک بحرانی و بدون ارزش تحلیلی اضافه (ADR‑004) |

| L6‑7 | backend/ابر برای همگام‌سازی یا تحلیل | افزایش سطح حمله بدون ارزش؛ تصمیم «فقط روی دستگاه» (ADR‑002) |
| L6‑8 | APIهای غیررسمی/مهندسی معکوس (Xbox, TikTok, Instagram, Roblox private endpoints) | خلاف ToS، ناپایدار، و مصداق «دورزدن محدودیت دسترسی» |
| L6‑9 | استفاده از Accessibility Service برای خواندن محتوای سایر اپ‌ها | سیاست Play بسیار سخت‌گیرانه و خارج از دامنه محصول |
| L6‑10 | هرگونه ارسال داده کاربر به سرویس تحلیل/تبلیغات | خلاف اصول امنیتی و حریم خصوصی سند حاضر |
| L6‑11 | جمع‌آوری `ANDROID_ID`/شناسه‌های دستگاهی برای همبستگی | از اندروید ۸ per‑app‑signing است و ارزش همبستگی ندارد؛ فقط ریسک دارد |
| L6‑12 | تشخیص چهره/اثر انگشت برای همبستگی هویت | خارج از دامنه، داده زیستی = دسته خاص GDPR Art. 9 |
