## ۲. قابلیت‌های تکمیل‌شده در این مرحله

این مرحله **تحویل مستندات** بود، نه کد. خروجی‌های تکمیل‌شده:

1. **پوشش کامل دسته‌های منبع:** هر ۱۶ دسته درخواستی + ۱۴ دسته کشف‌شده جدید بررسی شد (بیش از ۱۰۰ ردیف منبع در ۱۲ دسته‌بندی A…L). هیچ دسته‌ای بدون بررسی نمانده (معیار G1).
2. **جدول ۱۲ فیلدی برای هر منبع:** نوع ردپا، روش مجاز دسترسی، نیاز به OAuth، مجوز اندروید، فرمت، امکان تاریخ واقعی ثبت‌نام، محدودیت/سیاست، پیچیدگی، روش تست، وضعیت پیشنهادی، جایگزین مجاز.
3. **سه‌دسته‌بندی قابلیت‌ها:** مستقیم و قانونی / با اقدام کاربر / غیرقابل دسترسی + جایگزین، به‌علاوه دسته «آگاهانه رد شده».
4. **فهرست ۱۱ منبع دارای تاریخ واقعی ثبت‌نام** و تفکیک صریح آن از شواهد غیرمستقیم (اجرای قانون ۶).
5. **معماری قابل اجرا:** ساختار ۴۰+ ماژول، قرارداد Connector، موتور همبستگی با وزن و آستانه مستند، dedup پنج‌لایه، خط زمانی با `TimeFact`، مدیریت اسکن با checkpoint، گزارش پوشش شش‌وضعیتی.
6. **مدل داده کامل:** ۲۰+ موجودیت با فیلد، نوع، ایندکس، DDL نمونه و بودجه عملکردی.
7. **مدل امنیتی:** ۱۶ تهدید، معماری Keystore+Tink+SQLCipher، TokenVault، سه لایه redaction با ۷ تست دروازه‌ای، ۵ سطح حذف، انطباق Play و GDPR.
8. **نقشه راه ۱۳ فازی** با خروجی، تست، وابستگی، ریسک و Definition of Done.
9. **معیارهای پذیرش تست‌پذیر** برای هر فاز (بیش از ۹۰ معیار) + قالب گزارش پایان فاز.
10. **تثبیت ۲۰ تصمیم معماری** و ثبت ۱۰ مورد مبهم نیازمند تصمیم کاربر.

## ۳. تست‌های اجراشده

**هیچ تست خودکاری اجرا نشد — چون در این مرحله هیچ کدی نوشته نشده است.** این یک گزارش صادقانه است، نه ادعای موفقیت تست (قانون ۱۲).

کارهای راستی‌آزمایی انجام‌شده در این مرحله:

| اقدام | نتیجه |
| --- | --- |
| بررسی وضعیت مخزن (`git status`, `git log`, `find`) | مخزن تمیز؛ فقط `README.md` و `Rules`؛ بدون کد، بدون تست، بدون CI |
| پژوهش منابع رسمی و جاری (۱۹ جست‌وجوی وب روی مستندات گوگل/مایکروسافت/اندروید/HIBP/GDPR/Play Policy + منابع فنی) | ۲۵ ادعای کلیدی با منبع رسمی یا دست‌دوم مستند شد |
| تفکیک ادعاهای رسمی از دست‌دوم | ۱۲ مورد با ⚠️ در `limitations.md` (V‑1…V‑12) برای راستی‌آزمایی در فاز اجرا ثبت شد |
| کنترل صحت متن مستندات (اسکن کاراکترهای غیرفارسی/لاتین ناخواسته) | پاک شد؛ اسکن نهایی صفر یافته |

**موارد تست‌نشده و دلیل:** همه معیارهای پذیرش P0…P12 — چون هنوز پیاده‌سازی شروع نشده. اولین تست‌های واقعی در P0 (build + CI + unit) اجرا می‌شوند.

## ۵. محدودیت‌های فنی کشف‌شده در این مرحله

مهم‌ترین‌ها (فهرست کامل در `docs/limitations.md`):

- `READ_SMS`/`READ_CALL_LOG` عملاً برای این اپ بسته است → جایگزین: import فایل XML/CSV توسط کاربر.
- داده مرورگرهای اندروید و داده سایر اپ‌ها غیرقابل دسترسی است.
- `GET_ACCOUNTS` از API 26 فهرست حساب‌ها را نمی‌دهد.
- Facebook/Instagram/Amazon/eBay/Xbox/PSN/Nintendo API شخصی ندارند → فقط آرشیو رسمی.
- sign‑in logs مایکروسافت فقط با tenant سازمانی + لایسنس Entra ID P1/P2.
- `androidx.security:security-crypto` deprecated است → Tink + DataStore + Keystore.
- Google Sign‑In قدیمی deprecated/حذف‌شده → Credential Manager.
- Basic Auth مایکروسافت برای IMAP/POP/SMTP در حال حذف کامل است → XOAUTH2.
- Room 3.0 در راه است ولی SQLCipher با driver API جدید سازگار نیست → Room 2.8 در حالت سازگاری.
- سهمیه‌های سخت: Gmail (۶٬۰۰۰ واحد/دقیقه/کاربر)، YouTube (۱۰٬۰۰۰ واحد/روز)، GitHub (۵٬۰۰۰/ساعت)، Reddit (۱۰۰ QPM + تأیید دستی)، X (pay‑per‑use).
- targetSdk 36 از ۲۰۲۶‑۰۸‑۳۱ برای انتشار در Play الزامی است.
- `WorkManager.Data` سقف ~۱۰KB دارد → cursor باید در Room باشد.
- Foreground service نوع `dataSync` محدودیت زمانی دارد → اسکن بزرگ باید قطعه‌قطعه شود.
