# قابلیت‌های کشف‌شده و دسته‌بندی آن‌ها — Discovered Capabilities

> مرحله ۱ — تاریخ پژوهش: ۲۰۲۶‑۱۰‑۱۴
> این سند قابلیت‌های محصول را به سه دسته تقسیم می‌کند و قابلیت‌های **جدیدی** را که در پژوهش پیدا شد (خارج از فهرست اولیه درخواست) با ارزش واقعی، منبع داده، محدودیت، هزینه پیاده‌سازی و ریسک حریم خصوصی ثبت می‌کند.
>
> اصل حاکم: **قابلیت غیرقابل دسترسی به‌عنوان قابلیت پیاده‌سازی‌شده معرفی نمی‌شود.** هر ادعا باید منبع داده مشخص و شاهد داشته باشد.

## بخش ۱ — دسته‌بندی سه‌گانه قابلیت‌ها

### دسته ۱: قابل پیاده‌سازی مستقیم و قانونی

بدون نیاز به دورزدن هیچ محدودیتی؛ فقط ورود کاربر (OAuth) یا یک مجوز عادی اندروید.

| قابلیت | منبع داده (ID کاتالوگ) | خروجی برای کاربر |
| --- | --- | --- |
| کشف حساب‌ها از روی ایمیل‌های ثبت‌نام/تأیید/بازیابی رمز | A1, A2, A3, A4, A6 | فهرست سرویس‌ها + اولین شاهد + تاریخ مشاهده |
| خط زمانی رویدادهای امنیتی (ورود جدید، تغییر رمز، هشدار) | A1–A6 | رویدادهای مرتب‌شده با منشأ |
| کشف اشتراک‌های فعال از رسیدها و ایمیل‌های تمدید | A1–A6, E6 | فهرست اشتراک + دوره + مبلغ + شاهد |
| شناسه و پروفایل حساب گوگل روی دستگاه | B1 | حساب‌های متصل با وضعیت دسترسی |

| حساب GitHub/GitLab/Stack Exchange با تاریخ ساخت واقعی | G1, G2, G4 | تاریخ ثبت‌نام تأییدشده + فعالیت |
| حساب Steam با `timecreated` واقعی و کتابخانه بازی | F1 | تاریخ ثبت‌نام + بازی‌ها |
| حساب Last.fm / Fitbit با تاریخ عضویت واقعی | L2, L4 | تاریخ ثبت‌نام |
| تاریخچه مرورگر و بوکمارک‌های همگام‌شده | H1, H3, H5 | دامنه‌های بازدیدشده + بوکمارک‌ها |

| تاریخ اولین نسخه آرشیوشده پروفایل (Wayback) | J1 | شاهد وجود حساب در تاریخ X |
| تاریخ ثبت دامنه‌های کاربر | J2, G15 | تاریخ واقعی ثبت |
| ایمیل‌های تأییدشده در کلیدهای OpenPGP | A10 | هویت‌های ایمیلی + تاریخ کلید |
| Mastodon/Discord/Twitch/Reddit از طریق API رسمی | D4, D5, D9, D3 | پروفایل + فعالیت |
| واردکردن هر فایل/آرشیوی که کاربر انتخاب می‌کند | I8, L14, K2 | شواهد با منشأ فایل |

### دسته ۲: قابل پیاده‌سازی با اقدام یا تأیید کاربر

نیاز به یک اقدام آگاهانه دارد: ساخت کلید API، واردکردن فایل خروجی رسمی، فعال‌کردن مجوز خاص در Settings، یا رضایت جداگانه.

| قابلیت | اقدام لازم کاربر | ریسک/نکته |
| --- | --- | --- |
| اتصال Gmail API | ساخت پروژه GCP، OAuth consent، تأیید اپ | اسکوپ Restricted؛ برای انتشار عمومی نیازمند verification + ارزیابی امنیتی |
| واردکردن Google Takeout | ساخت آرشیو و انتقال به دستگاه | حجم زیاد، چندتکه، زمان آماده‌سازی |
| واردکردن آرشیو Meta/Amazon/Apple/LinkedIn/Microsoft/Discord/TikTok/Snapchat | درخواست داده از سرویس | زمان انتظار، قالب متغیر |
| واردکردن CSV مدیریت‌کننده رمز | صدور فایل از ابزار رمز | **بسیار حساس** → فقط metadata ذخیره می‌شود |
| اسکن QR خروجی Google Authenticator | اسکن با دوربین | فقط issuer/account ذخیره می‌شود، secret هرگز |
| واردکردن XML پیامک‌ها | نصب اپ صادرکننده توسط کاربر | جایگزین مجاز `READ_SMS` |
| مجوز دسترسی به Usage Stats | فعال‌سازی در Settings | داده بسیار حساس؛ افشای برجسته لازم است |
| مجوز مخاطبان/تقویم | runtime permission | فقط برای هویت‌های خود کاربر |
| Notification Listener | فعال‌سازی دومرحله‌ای در Settings | خاموش به‌صورت پیش‌فرض + allowlist + redaction |
| کلیدهای API پولی (HIBP, X, Riot, …) | خرید/ساخت کلید توسط کاربر | اپ هیچ کلیدی را hardcode نمی‌کند |
| اتصال Health Connect | مجوز per‑data‑type | داده سلامت؛ فقط با رضایت جدا |
| صرافی رمزارز با کلید read‑only | ساخت کلید + IP whitelist | ریسک بالا؛ فاز آخر |
| نمونه‌های خودمیزبان (GitLab/Moodle/Discourse) | واردکردن URL + توکن | اعتماد به سرور کاربر |

## بخش ۲ — قابلیت‌های جدید کشف‌شده در پژوهش

هر مورد با پنج فیلد الزامی: **ارزش واقعی، منبع داده، محدودیت، هزینه پیاده‌سازی، ریسک حریم خصوصی**.

### NC‑01 — تاریخ نصب واقعی اپ‌ها روی دستگاه
- **ارزش واقعی:** بالا. `PackageInfo.firstInstallTime`/`lastUpdateTime` تنها شاهد زمانی **قابل اتکا و آفلاین** درباره زندگی دیجیتال کاربر روی این دستگاه است و بدون هیچ شبکه‌ای به دست می‌آید.
- **منبع داده:** I1/I1b (PackageManager).
- **محدودیت:** از اندروید ۱۱ فهرست فیلتر است؛ `QUERY_ALL_PACKAGES` نیازمند Declaration Form در Play است و ممکن است رد شود → fallback به `<queries>` هدفمند.
- **هزینه پیاده‌سازی:** S (یک connector + یک صفحه گزارش).
- **ریسک حریم خصوصی:** متوسط. فهرست اپ‌های نصب‌شده داده شخصی حساس است؛ فقط روی دستگاه می‌ماند و در گزارش‌های خطا ظاهر نمی‌شود.

### NC‑02 — خط زمانی استفاده از اپ‌ها (Usage Stats)
- **ارزش واقعی:** بالا برای «چه زمانی حساب X واقعاً استفاده شده»؛ تفکیک «نصب» از «استفاده».
- **منبع داده:** I2 (`UsageStatsManager.queryEvents`).
- **محدودیت:** special app‑op (هدایت کاربر به Settings)، داده فقط برای بازه‌ای که سیستم نگه داشته، دقت رویدادها به سیاست OEM وابسته است.
- **هزینه:** L (صف رویداد، تجمیع، UI خط زمانی).
- **ریسک:** بالا → افشای برجسته، رضایت جدا، خاموش به‌صورت پیش‌فرض، ذخیره تجمیعی نه خام.

### NC‑03 — کشف حساب‌های همگام‌شده از روی مخاطبان
- **ارزش واقعی:** بالا و کمتر شناخته‌شده: `ContactsContract` رکوردهای raw با `ACCOUNT_NAME`/`ACCOUNT_TYPE` دارد → ایمیل‌های دیگر کاربر و سرویس‌هایی که روی دستگاه همگام شده‌اند بدون `AccountManager` دیده می‌شوند.
- **منبع داده:** I3.
- **محدودیت:** از API 26 `AccountManager.getAccounts()` بدون انتخاب کاربر فهرست کامل نمی‌دهد، اما مسیر مخاطبان کار می‌کند؛ نیازمند `READ_CONTACTS`.
- **هزینه:** M.
- **ریسک:** بالا (داده اشخاص ثالث) → فقط ایمیل/نوع حساب **متعلق به خود کاربر** استخراج می‌شود؛ مخاطبان دیگران به‌صورت انبوه ذخیره نمی‌شوند (ADR‑011).

### NC‑04 — گزارش مجوزهای سایر اپ‌ها
- **ارزش واقعی:** متوسط–بالا؛ پاسخ به «کدام اپ به دوربین/موقعیت/میکروفون دسترسی دارد» که بخشی از ردپای دیجیتال است و در فهرست اولیه کاربر هم آمده.
- **منبع داده:** I10 (`PackageManager.checkPermission`).
- **محدودیت:** فقط برای پکیج‌های قابل مشاهده؛ نیازمند همان استراتژی NC‑01.
- **هزینه:** M.
- **ریسک:** متوسط؛ داده حساس ولی بدون شبکه.

### NC‑05 — XML پیامک‌ها به‌عنوان جایگزین مجاز `READ_SMS`
- **ارزش واقعی:** خیلی بالا. پیامک‌ها شاهد اصلی OTP، تأیید شماره، هشدار بانک و ثبت‌نام سرویس‌های محلی‌اند؛ چون `READ_SMS` عملاً برای ما بسته است، این تنها مسیر مجاز است.
- **منبع داده:** I5b (قالب `SMS Backup & Restore`).
- **محدودیت:** کاربر باید اپ صادرکننده را نصب و فایل را منتقل کند؛ قالب XML پایدار ولی غیررسمی است.
- **هزینه:** S–M (یک پارسر XML + نگاشت).
- **ریسک:** بالا (متن پیامک) → ذخیره فقط فیلدهای لازم، رمزگذاری، و امکان حذف انتخابی.

### NC‑06 — فهرست سرویس‌های دارای 2FA از QR خروجی Google Authenticator
- **ارزش واقعی:** بالا و کاملاً جدید: payload `otpauth-migration://` یک protobuf رسمی گوگل است که `issuer` و `accountName` هر ورودی را دارد → نقشه فشرده‌ای از حساب‌های مهم کاربر.
- **منبع داده:** L5.
- **محدودیت:** نیاز به `CAMERA` و اسکن دستی؛ فقط Google Authenticator (سایر ابزارها مسیر L6 را دارند).
- **هزینه:** M (protobuf decode + UI اسکن).
- **ریسک:** بسیار بالا اگر secret ذخیره شود → **secret هرگز ذخیره، لاگ یا نمایش داده نمی‌شود** (ADR‑004).

### NC‑07 — metadata صادرات مدیریت‌کننده‌های رمز
- **ارزش واقعی:** بالا؛ سریع‌ترین راه برای دیدن «در چند صد سرویس حساب دارم».
- **منبع داده:** L6, H2.
- **محدودیت:** چندین قالب (JSON, CSV, 1PUX, KDBX)؛ KDBX نیاز به رمز master دارد.
- **هزینه:** M.
- **ریسک:** بحرانی → فقط `url/username/issuer`؛ ستون رمز دور ریخته می‌شود و تست خودکار تضمین می‌کند هیچ رمزی در DB/لاگ نیست.

### NC‑08 — Wayback CDX برای تاریخ وجود پروفایل
- **ارزش واقعی:** بالا؛ برای سرویس‌هایی که API ندارند و آرشیو هم نمی‌دهند، اولین تصویر آرشیوشده یک شاهد زمانی قابل استناد است.
- **منبع داده:** J1.
- **محدودیت:** فقط URLهایی که کاربر تأیید کرده؛ پوشش Wayback ناقص است؛ نرخ محدود.
- **هزینه:** S.
- **ریسک:** کم؛ ولی URL در لاگ شبکه ثبت نشود (redaction).

### NC‑09 — جست‌وجوی کامیت با ایمیل کاربر (GitHub Search API)
- **ارزش واقعی:** متوسط–بالا؛ سازمان‌ها/مخازنی را پیدا می‌کند که کاربر با ایمیل شخصی‌اش در آن‌ها کامیت زده → کشف سوابق کاری/پروژه‌ای.
- **منبع داده:** G5.
- **محدودیت:** محدودیت نرخ search؛ فقط ایمیل‌های خود کاربر و با رضایت صریح.
- **هزینه:** M.
- **ریسک:** متوسط (ایمیل در query string) → query هرگز لاگ نمی‌شود.

### NC‑10 — کلیدهای OpenPGP و ایمیل‌های تأییدشده
- **ارزش واقعی:** متوسط؛ هویت‌های ایمیلی فراموش‌شده و تاریخ ساخت کلید را نشان می‌دهد.
- **منبع داده:** A10 (keys.openpgp.org).
- **محدودیت:** فقط کلیدهای آپلودشده؛ هش ایمیل در URL → باید redact شود.
- **هزینه:** S.
- **ریسک:** کم–متوسط.

### NC‑11 — RDAP/WHOIS برای دامنه‌های کاربر
- **ارزش واقعی:** متوسط؛ **تاریخ واقعی ثبت دامنه** و زنجیره رجیسترارها.
- **منبع داده:** J2, G15, J3.
- **محدودیت:** کاربر باید دامنه‌ها را بدهد یا از ایمیل استخراج شوند.
- **هزینه:** S.
- **ریسک:** کم.

### NC‑12 — «دستیار درخواست داده» (Data Subject Request Assistant)
- **ارزش واقعی:** **خیلی بالا و استراتژیک.** بیشتر سرویس‌ها API ندارند اما طبق GDPR Art. 15/20 موظف‌اند داده را در قالب ساختاریافته/ماشین‌خوان و ظرف یک ماه بدهند. یک کاتالوگ داخلی (مسیر دقیق در هر سرویس + نامه آماده + قالب مورد انتظار + مهلت) عملاً ده‌ها منبع قفل‌شده را باز می‌کند و کاملاً قانونی است.
- **منبع داده:** K1, K3 + همه importerهای دسته D/E/C.
- **محدودیت:** زمان انتظار کاربر (روزها تا هفته‌ها)؛ قالب‌ها تغییر می‌کنند.
- **هزینه:** M برای کاتالوگ و UX + هزینه هر importer به‌صورت جدا.
- **ریسک:** کم (هیچ دسترسی خودکاری به سرویس‌ها نیست).

### NC‑13 — تحلیل سرصفحه‌های ایمیل (forensic headers)
- **ارزش واقعی:** بالا؛ از `Received`/`DKIM`/`ARC`/`Return-Path`/`List-Unsubscribe` می‌توان اولین تماس واقعی با هر سرویس، دامنه ارسال‌کننده، و اشتراک‌های خبرنامه‌ای را استخراج کرد.
- **منبع داده:** A5.
- **محدودیت:** سرصفحه‌ها توسط سرویس‌ها دستکاری/حذف می‌شوند؛ دقت باید صادقانه برچسب بخورد.
- **هزینه:** M.
- **ریسک:** متوسط (IP در سرصفحه) → IPها فقط به‌صورت تجمیعی/کشور نمایش داده می‌شوند مگر کاربر انتخاب کند.

### NC‑14 — تشخیص «اتصال حساب‌ها» (account linking)
- **ارزش واقعی:** بالا و در فهرست درخواست کاربر صراحتاً آمده. مسیرهای مجاز: Discord `/users/@me/connections`، GitHub `/user/installations`، Microsoft «Apps you've given access to»، Google «Third‑party apps with account access» (فقط با اقدام کاربر)، و همبستگی ایمیل/نام کاربری بین منابع.
- **منبع داده:** D5, G1, C3, B11 + موتور همبستگی داخلی.
- **محدودیت:** برای گوگل API عمومی ندارد → ورود دستی/فایل.
- **هزینه:** M–L.
- **ریسک:** متوسط.

### NC‑15 — تشخیص حساب‌های حذف‌شده/غیرفعال از شواهد باقی‌مانده
- **ارزش واقعی:** متوسط–بالا (درخواست صریح کاربر). شواهد: ایمیل «your account was deleted/deactivated»، آخرین پیام قبل از قطع شدن، رد شدن API با `404 user not found` پس از اینکه قبلاً موفق بوده، نقض داده قدیمی برای حسابی که امروز وجود ندارد.
- **منبع داده:** A1–A6, A7, + تاریخچه connector خودمان (snapshot قبلی).
- **محدودیت:** **هرگز نمی‌توان قطعی گفت**؛ فقط با برچسب `PROBABLE` + شاهد.
- **هزینه:** M (نیاز به نگهداری snapshot قبلی = تاریخچه connector).
- **ریسک:** متوسط (ذخیره تاریخچه نتایج).

### NC‑16 — رصد تغییرات هویت (نام کاربری/ایمیل/شماره)
- **ارزش واقعی:** بالا؛ با مقایسه snapshotهای متوالی connectorها (مثلاً `login` قبلی و فعلی GitHub) تغییر نام کاربری و ایمیل کشف و در خط زمانی ثبت می‌شود.
- **منبع داده:** همه connectorهای دارای پروفایل + موتور dedup.
- **محدودیت:** فقط از زمانی که اپ نصب است؛ گذشته از طریق Takeout/آرشیوها بازسازی می‌شود.
- **هزینه:** M.
- **ریسک:** متوسط.

### NC‑17 — گزارش «پوشش صادقانه» (Coverage Honesty Report)
- **ارزش واقعی:** بسیار بالا برای اعتماد؛ به‌جای ادعای کامل‌بودن، ماتریس «کدام دسته بررسی شد، با کدام منبع، چند شاهد، چه چیزی غیرقابل دسترس بود و چرا» نشان می‌دهد.
- **منبع داده:** CoverageRecord/ErrorRecord در مدل داده.
- **محدودیت:** نیاز به طراحی دقیق وضعیت‌ها (DISCOVERED/PROBABLE/CONFIRMED/INACCESSIBLE/NOT_CHECKED/NO_RESULT).
- **هزینه:** M.
- **ریسک:** کم.

### NC‑18 — سلامت امنیتی حساب‌ها
- **ارزش واقعی:** بالا؛ ترکیب «حساب کشف‌شده» + «در نقض داده بوده» (A7) + «رمزش در leak بوده» (A8) + «2FA دارد» (L5/L6) → یک امتیاز ریسک قابل فهم برای هر حساب.
- **منبع داده:** A7, A8, L5, L6.
- **هزینه:** M.
- **ریسک:** متوسط (A8 فقط با اقدام کاربر و k‑anonymity).

### NC‑19 — خط زمانی مکان (Location History/Timeline)
- **ارزش واقعی:** بالا برای «کجا بودم و چه حسابی آنجا استفاده شد»؛ اما داده بسیار حساس.
- **منبع داده:** B5 (Takeout Location History/Timeline).
- **محدودیت:** فرمت Takeout در ۲۰۲۴–۲۰۲۵ از `Location History.json` به `Timeline` تغییر کرد ⚠️ → هر دو پارس می‌شوند.
- **هزینه:** L (داده حجیم، نیاز به streaming و downsampling).
- **ریسک:** بحرانی → پیش‌فرض خاموش، ذخیره تجمیعی، حذف آسان.

### NC‑20 — واردکننده چندتکه/بزرگ با ادامه از نقطه توقف
- **ارزش واقعی:** بالا؛ آرشیوهای واقعی چند گیگابایت و چند ZIP تکه‌شده‌اند. بدون streaming و checkpoint عملاً غیرقابل استفاده است (و قانون ۹ هم الزام می‌کند).
- **منبع داده:** I8, K2, L14.
- **محدودیت:** محدودیت حافظه اندروید؛ grant SAF ممکن است از دست برود.
- **هزینه:** L.
- **ریسک:** کم.

### NC‑21 — کاتالوگ سرویس‌های آلمانی/اروپایی (بومی‌سازی)
- **ارزش واقعی:** متوسط–بالا برای کاربر ساکن آلمان: Xing, Telekom, Otto, Zalando, Check24, Klarna, Deutsche Post, PayPal DE + متن نامه GDPR به آلمانی.
- **منبع داده:** L9, K1.
- **محدودیت:** نیاز به متن حقوقی بازبینی‌شده (این اپ مشاوره حقوقی نمی‌دهد).
- **هزینه:** S–M.
- **ریسک:** کم.

### NC‑22 — کاتالوگ سرویس‌های ایرانی/فارسی
- **ارزش واقعی:** بالا برای کاربر فارسی‌زبان (دیجی‌کالا، اسنپ، تپسی، دیوار، بازار، بانک‌ها، سامانه‌های دولتی).
- **منبع داده:** E7, K1.
- **محدودیت:** تقریباً هیچ‌کدام API عمومی ندارند؛ دسترسی از بعضی مناطق/شبکه‌ها محدود است؛ متن نامه درخواست داده باید فارسی باشد.
- **هزینه:** M (بیشتر محتوایی است تا فنی).
- **ریسک:** کم.

### NC‑23 — واردکننده آرشیو Apple/Microsoft/Amazon/Snapchat/TikTok
- **ارزش واقعی:** بالا؛ هر کدام ده‌ها شاهد زمانی می‌دهند.
- **منبع داده:** E1, E5, C3, D10, D11.
- **هزینه:** M هر کدام.
- **ریسک:** متوسط.

### NC‑24 — گزارش‌گیری و صادرات نتیجه (بدون داده خام)
- **ارزش واقعی:** بالا؛ کاربر می‌تواند خلاصه را PDF/JSON صادر کند؛ برای حسابرسی شخصی و موارد حقوقی.
- **محدودیت:** صادرات نباید توکن/رمز/مقدار کوکی شامل شود.
- **هزینه:** M. **ریسک:** متوسط (فایل خروجی رمزنگاری‌شده با عبارت عبور).

### NC‑25 — حالت «بدون شبکه» کامل
- **ارزش واقعی:** بالا؛ همه منبع‌های محلی (I1, I1b, I10, A6, H2, L5, L6, I5b, L14) آفلاین کار می‌کنند → ارزش محصول حتی بدون هیچ OAuth.
- **هزینه:** معماری (همه connectorها باید `requiresNetwork` را اعلام کنند).
- **ریسک:** کم.
